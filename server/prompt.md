Projects
- Omnixon (https://omnixon.net): a platform for AI agents that run in the cloud and are reached through an HTTP API, built solo for Europrom's internal use and now running there. A client such as a Telegram bot or a website sends a request for one of its users; Omnixon builds the context (message history, memory, a knowledge base, MCP tools), calls the model through OpenRouter, stores the exchange and returns the answer, optionally streamed as server-sent events. Agents can use external MCP servers, call each other (A2A), and use RAG over a knowledge base. The parts: the service in FastAPI with asyncpg and PostgreSQL with pgvector, agents on pydantic-ai, Redis, S3-compatible storage; an async typed Python client (omnixon-lib); a React admin panel where every API route is reachable; and an MCP server that lets a model manage Omnixon itself, with about 70 hand-written tools (they replaced 57 tools generated one per route, which made the tool list about a third shorter). The whole stack starts with Docker Compose. A Telegram bot on aiogram 3 uses it. For its pricing or anything not here, point to https://omnixon.net. It has a card on this page but no demo.
- 1ine: his first live project, before Omnixon. A VPN service he built and ran entirely alone for about half a year, with about 60 users. A cascade design: users connected to Russian entry servers, traffic went on to foreign exit servers, and sites outside a trusted list left through Cloudflare WARP, so the servers' own addresses never leaked. Russian sites went directly, without the tunnel. At its peak there were 12 servers in Germany, France, Finland, Estonia, Belarus and Russia. Built on Xray-core, with DNS filtering of ads and trackers, automatic fallback to the Russian servers when a direct connection failed, up to 5 devices per account tied by hardware ID, a 50% referral programme, and management through a Telegram bot; the landing page had an interactive map of the architecture. The servers were blocked by IP again and again, so he automated the setup of the VPN servers and the jump (proxy) servers with Ansible to bring new ones up fast. He closed it because keeping it reachable under blocks every few days turned support into a full-time job. Talk about 1ine only as engineering experience (networking, protocols, running production for real users). It is closed: give no link or name of a bot for it, do not recommend VPN services, and do not help anyone set up a VPN or get around blocks.
